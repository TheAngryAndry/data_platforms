# Домашнее задание №2: YARN и веб-интерфейсы

Развёртывание YARN и публикация веб-интерфейсов основных и вспомогательных демонов кластера через nginx на edge. Дедлайн: 12.10, 23:59.

## Зависимость от ДЗ1

Для запуска нужен кластер из [hw1](../hw1/README.md): Java 11 и Hadoop 3.4.2 на внутренних узлах, работающие NameNode, SecondaryNameNode и три DataNode, исправный HDFS. В этой папке только ДЗ2, без установщика HDFS и его исходных конфигураций. На чистых серверах скрипт остановится до установки YARN.

Скрипт копирует с NameNode действующие `core-site.xml` и `hdfs-site.xml`, а также установленный дистрибутив Hadoop для edge. На NodeManager он использует Java, Hadoop и конфигурацию HDFS из ДЗ1. Исходная папка `hw1` для этого не нужна.

## Запуск

На локальной машине нужны `bash`, `ssh`, `tar`, `curl` и ключ `~/.ssh/id_ed25519_mts_course`. На edge нужны `bash`, `curl`, `ssh`, `scp`, `tar` и ключ `~/.ssh/team_internal`. Пользователь `team` должен иметь доступ к внутренним узлам и `sudo` без пароля.

Из корня репозитория:

```bash
./hw2/scripts/deploy.sh
```

Из папки `hw2` запускайте `./scripts/deploy.sh`. Другой путь к ключу можно передать через `LOCAL_SSH_KEY`. Скрипт копирует файлы ДЗ2 в `~/data-platforms/hw2` на edge и NodeManager, проверяет HDFS и устанавливает YARN и nginx. HDFS продолжает работать без форматирования и перезапуска.

При повторном запуске скрипт сохраняет предыдущую конфигурацию в `/var/backups/data-platforms.*`, обновляет настройки и перезапускает YARN. Перед запуском дождитесь завершения работающих задач.

## Устройство и доступ

ResourceManager, встроенный WebAppProxy и JobHistoryServer работают на `team-01-en`. NodeManager работают на `team-01-00` и `team-01-01`: на каждом узле для контейнеров выделены 2048 MiB и 2 vCPU. На `team-01-nn` остаются NameNode, SecondaryNameNode и DataNode, чтобы сохранить память для HDFS при 3.8 GiB RAM.

В `config/` находятся настройки, в `systemd/` файлы сервисов, в `nginx/` конфигурация nginx. Адреса заданы для кластера `team-01`. При переносе на другой кластер измените `cluster.conf`, XML и конфигурацию nginx.

Скрипт устанавливает конфигурацию YARN в `/etc/hadoop/yarn-conf` и берёт окружение из `config/yarn-env.sh`. В HDFS создаёт каталоги `/logs`, `/mr-history`, `/user/team` и общий `/tmp`. Настройки включают `mapreduce_shuffle`, запуск MapReduce через YARN и агрегацию логов в HDFS. Контейнеры AM, map и reduce получают по 512 MiB с Java heap 256 MiB.

На edge и узлах NodeManager скрипт исправляет записи имен кластера в `/etc/hosts`: короткие имена и FQDN должны разрешаться во внутренние IP, а не в `127.0.1.1`. Исходный файл сохраняется в резервной копии. Без этого Hadoop RPC может привязаться к loopback даже при указанном внутреннем IP.

Для чтения истории задач и агрегации логов нужны пользователи `yarn` и `mapred` на NameNode: именно там HDFS определяет их группы. Скрипт создаёт этих пользователей и обновляет кеш групп без перезапуска HDFS.

Для доступа из браузера запустите команду на локальной машине и оставьте терминал открытым:

```bash
./hw2/scripts/open-web.sh
```

Скрипт открывает девять локальных портов через одно SSH-соединение к edge. Эти порты должны быть свободны. Чтобы закрыть туннель, нажмите `Ctrl+C`. Внешняя сеть учебного стенда пропускает только порт 22, поэтому доступ к интерфейсам настроен через SSH. Для этого не нужна панель облака.

Веб-интерфейсы доступны через туннель и nginx на edge:

| Демон | Узел | Адрес после запуска туннеля |
| --- | --- | --- |
| NameNode | team-01-nn | [9870](http://127.0.0.1:9870/dfshealth.html) |
| SecondaryNameNode | team-01-nn | [9868](http://127.0.0.1:9868/) |
| DataNode | team-01-nn | [9864](http://127.0.0.1:9864/datanode.html) |
| DataNode | team-01-00 | [9865](http://127.0.0.1:9865/datanode.html) |
| DataNode | team-01-01 | [9869](http://127.0.0.1:9869/datanode.html) |
| ResourceManager / WebAppProxy | team-01-en | [8088](http://127.0.0.1:8088/cluster) |
| NodeManager | team-01-00 | [8042](http://127.0.0.1:8042/node) |
| NodeManager | team-01-01 | [8043](http://127.0.0.1:8043/node) |
| JobHistoryServer | team-01-en | [19888](http://127.0.0.1:19888/jobhistory) |

nginx заменяет внутренние адреса в ссылках и перенаправлениях на адрес, с которого открыт интерфейс. Разрешены только GET и HEAD. Кластер учебный, без Kerberos. При использовании туннеля доступ защищен SSH-ключом.

Правило iptables разрешает доступ к новым backend-портам `8030–8033`, `10020`, `10033`, `18088`, `19889` только из внутренней сети `10.1.0.0/24`. Сервис `hadoop-web-firewall` восстанавливает это правило. Общая политика firewall и настройки SSH не меняются.

Для прямого HTTP-доступа без SSH попросите администратора облака открыть веб-порты из таблицы. После этого используйте `171.22.72.148` вместо `127.0.0.1`: nginx уже настроен. Root-доступ на VM не позволяет изменить внешний firewall.

Проверку можно повторить на edge:

```bash
bash ~/data-platforms/hw2/scripts/verify-edge.sh
```

Скрипт проверяет сервисы, два зарегистрированных NodeManager и три DataNode, запускает WordCount через YARN и сравнивает результат с ожидаемым. Затем проверяет статус `SUCCEEDED`, наличие задачи в JobHistoryServer, агрегированные логи, `hdfs fsck /` и все веб-интерфейсы. Входные данные и результат остаются в отдельном каталоге `/user/team/data-platforms-*` в HDFS.

Для проверки веб-интерфейсов с локальной машины скрипт сам открывает и закрывает туннель:

```bash
./hw2/scripts/open-web.sh --check
```

Если туннель уже открыт, запустите `./hw2/scripts/verify-web.sh`. После открытия портов прямой публичный доступ можно проверить командой `VERIFY_HOST=171.22.72.148 ./hw2/scripts/verify-web.sh`. Проверка в конце `deploy.sh` проходит через SSH-туннель.

## Диагностика и файлы

`bash hw2/tests/deploy.sh` из корня репозитория проверяет отдельный запуск ДЗ2, остановку при ошибке и отказ при отсутствующем HDFS без подключения к кластеру.

При ошибке скрипты останавливаются. Логи сервисов можно посмотреть через `sudo journalctl -u yarn-resourcemanager`, `-u yarn-nodemanager` и `-u mapred-historyserver` на соответствующем узле. Логи Hadoop находятся в `/var/log/hadoop-yarn` и `/var/log/hadoop-mapred`.

- `scripts/deploy.sh`: запуск только ДЗ2 с локальной машины.
- `scripts/deploy-yarn-edge.sh`, `scripts/install-yarn.sh`: установка YARN и резервная копия настроек.
- `scripts/configure-hosts.py`: исправление адресов кластера в `/etc/hosts`.
- `scripts/setup-hdfs.sh`: создание пользователей и каталогов для YARN и истории в существующем HDFS на NameNode.
- `scripts/firewall.sh`: ограничение доступа к backend-портам.
- `scripts/verify-edge.sh`: проверка HDFS, YARN и MapReduce.
- `scripts/verify-web.sh`: проверка веб-интерфейсов.
- `scripts/open-web.sh`: доступ к интерфейсам с локальной машины через SSH.

Результаты проверки на стенде через SSH-туннель сохранены в [verification.txt](verification.txt).
